DIAGNÓSTICO

O projeto AluERP está em fase inicial mas com problemas arquiteturais que
evitarão crescimento saudável. Os principais riscos são:

1. DUPLICAÇÃO DE CÓDIGO (99%)
   - ExpenseCategoryList ≈ IncomeCategoryList
   - Múltiplos CRUDLists com mesmo padrão
   - Impacto: Manutenção exponencialmente difícil

2. FALTA DE PADRÕES DE DADOS
   - Sem Repository Pattern
   - Sem Service Layer
   - Queries espalhadas por N locais
   - Impacto: Testabilidade 0%, reutilização 0%

3. LÓGICA DE NEGÓCIO NA UI
   - Cálculos em componentes
   - Validações em actions
   - Estado em múltiplos lugares
   - Impacto: Bugs, dificuldade em manutenção

4. PROPS DRILLING
   - 10+ props em componentes
   - Sem estado centralizado
   - Sem Context/Store
   - Impacto: Legibilidade ruim, propenso a bugs

5. SEM PERFORMANCE
   - Sem cache (SWR/React Query)
   - Sem memoização
   - Sem lazy loading
   - Sem código splitting
   - Impacto: Performance degradada com crescimento

RISCO DE NÃO FAZER

Se não refatorar nos próximos 2-3 sprints:

1. DÉBITO TÉCNICO EXPONENCIAL
   - Cada novo componente duplica 50% do anterior
   - Manutenção fica impossível

2. BUGS DIFFICEIS DE RASTREAR
   - Lógica espalhada
   - Estados duplicados
   - Sem testes

3. PERFORMANCE DEGRADADA
   - Sem cache: N requests por página
   - Sem memoização: Re-renders desnecessários
   - Sem lazy loading: Bundle grande

4. ONBOARDING IMPOSSÍVEL
   - Novo dev leva 2-3 semanas para entender
   - Código duplicado confunde
   - Sem padrões claros

5. NÃO ESCALÁVEL PARA PRODUÇÃO
   - Não pronto para múltiplos usuários
   - Sem tratamento de erros
   - Sem logging
